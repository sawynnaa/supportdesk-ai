# 决策：POST 流、精确检索与人工确认

- 客服问题需要请求体、CSRF 令牌和业务请求 ID，因此使用 fetch POST + SSE 响应而非原生 EventSource。终态保存进数据库，断线后读取快照，不假装支持事件重放。
- 小型知识库先使用 pgvector 精确检索，工作区及版本过滤在 SQL 中完成。模板模式的字符哈希向量存在碰撞，开发集显示无答案误匹配，因此补充字面证据过滤。没有宣称这等同于成熟语义检索。
- 模型只生成 title/description/priority。工作区、创建人和权限由服务端决定，负责人由本工作区成员选择。明确按钮触发草稿，另一次人工确认才产生业务工单。
- 请求级幂等防止重复网络请求，草稿级锁防止不同 key 重复确认，两者不能相互替代。
- 为满足无需数据库服务即可启动，增加 PGlite 开发模式；生产保留 PostgreSQL、Prisma 与独立 worker。两种路径使用同一 SQL 约束和同一套集成测试，但必须分别运行才能宣称各自通过。
