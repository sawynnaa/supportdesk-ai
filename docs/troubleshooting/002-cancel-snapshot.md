# 真实修复：取消不应覆盖最新部分答复

代码复查发现，取消接口最初直接将最近一次数据库快照写入终态；生成循环随后试图保存更新的文字，会被“只能从活动态进入终态”的条件拒绝。这意味着快照后的已显示内容可能丢失。

修改为：有本地活动任务时先 AbortController 中止生成，由生成循环保存内存中的最新文字并提交 cancelled。不存在本地任务时才用数据库快照取消，以支持重启/多实例路径。客户端先发取消请求，再中止读取。

回归测试在收到第一个文本事件后立即取消（特意早于常规快照），断言运行终态为 cancelled 且保存内容非空；同时测试第二个活动请求返回 409。此用例已通过。多实例远端取消仍可能仅保留最近持久快照，这一边界已写入架构说明。
